# Спецификация: приложение быстрого захвата задач

**Платформа:** Windows 10/11
**Версия документа:** v1.1 (закрыты пробелы, найденные при разборе перед разработкой)
**Статус:** готово к разработке v1

---

## 1. Суть продукта

Резидентное приложение, вызываемое глобальным горячим клавишам поверх всех окон. Один экран: поле ввода и список задач. Цель — время от нажатия хоткея до мигающего курсора в пределах 30–50 мс. Всё остальное подчинено этой метрике.

**Что входит в v1:** создание задач, заметки к задачам, важность, выполнение, удаление, ручной порядок, отмена действий, фильтрация, настройки, автозапуск.

**Что сознательно отложено:** даты и сроки, напоминания и системные уведомления, парсинг дат из текста, проекты и теги, подзадачи, повторяющиеся задачи, поиск по тексту заметок, экран статистики, синхронизация.

## 3. Архитектура процесса

- Приложение **резидентное**: висит в трее, окно скрыто, а не закрыто. Хоткей делает `Show()`, закрытие — `Hide()`. `Close()` не вызывается никогда, кроме выхода из приложения.
- **Запуск всегда тихий.** Ни автозапуск при входе в систему, ни первый запуск после установки, ни ручной запуск окно не показывают — приложение молча садится в трей. Окно появляется только по хоткею или через меню трея.
- **Прогрев окна при старте:** окно создаётся и сразу скрывается на запуске. Первый рендер WPF стоит 200–400 мс, и он не должен попадать на первое нажатие хоткея.
- **Single instance:** именованный `Mutex`. Второй запуск через `EventWaitHandle` сигналит первому экземпляру показать окно и завершается.
- **Элевация:** опция в настройках, по умолчанию выключена. Даёт единственное — срабатывание хоткея, когда в фокусе окно, запущенное от администратора. Переключение опции пересоздаёт задачу в Планировщике, а это само требует прав администратора: показывается UAC-запрос. **Уже запущенный процесс своих прав при этом не меняет** — элевированным он стартует при следующем входе в систему. Перезапускать приложение на месте не стали: это второй запрос UAC подряд ради минуты выигрыша. В настройках это подписано, чтобы галка не выглядела бесплатной.
- **Автозапуск:** только через Планировщик заданий (триггер «При входе в систему», галка «Выполнить с наивысшими правами»). Реестр `HKCU\...\Run` не используется — он вызывает запрос UAC при каждой загрузке.

### Известные ограничения платформы

- Хоткей не сработает над UAC-диалогом, экраном блокировки и эксклюзивным полноэкранным режимом в играх — ни при каком уровне прав.
- Перетаскивание файлов и текста **извне** в окно в v1 не поддерживается: дроп игнорируется. Когда дойдёт до v2 — в элевированное окно файлы из проводника не проходят вообще, UIPI режет `WM_DROPFILES`.

## 4. Глобальный хоткей

- **По умолчанию:** `Ctrl+Alt+Space`. Настраивается.
- Регистрируется на **message-only окне** (`HwndSource` с `HwndSourceParameters`), а не на главном окне, чтобы регистрация не умирала вместе с окном. `RegisterHotKey` + обработка `WM_HOTKEY`.
- Возврат `RegisterHotKey` **обязательно проверяется**. `false` означает, что комбинация занята другой программой — показывается уведомление и экран настройки хоткея.

### Три состояния при нажатии

| Текущее состояние | Действие |
|---|---|
| Окно скрыто | показать и передать фокус в поле ввода |
| Окно видно, фокуса нет | передать фокус, **не прятать** |
| Окно видно и в фокусе | спрятать |

- При клике мимо окна **окно не прячется**. Скрытие — только хоткеем или `Esc`.

## 5. Окно

### Геометрия и позиция

- Ширина изменяется мышью, значение сохраняется. Стартовое — 560 px.
- Максимальная высота настраивается и сохраняется. Потолок по умолчанию — 60% рабочей области, дальше скролл списка.
- Высота растёт по контенту до потолка.
- Появляется на мониторе, где находится курсор (`MonitorFromPoint`), с привязкой к углу **рабочей области** (`WorkArea`, не `ScreenBounds`), отступ 12–16 px от края.

### Угол привязки

Настройка: верхний левый / **верхний правый (по умолчанию)** / нижний левый / нижний правый.

- **Верхние углы:** поле ввода сверху, список растёт вниз.
- **Нижние углы:** поле ввода **снизу**, под списком, список растёт вверх (модель мессенджера). Это обязательно — иначе при добавлении задач поле ввода уезжает вместе с растущим окном и мышечная память не формируется.
- **Новая задача всегда появляется вплотную к полю ввода:** при верхних углах — первой строкой сверху, при нижних — первой строкой снизу. Список в обоих случаях растёт от поля ввода наружу. Формулировка «новые наверх» из раздела 9 означает «в начало списка», а не «визуально вверху экрана».
- Анимация появления идёт от угла привязки, а не из центра.

### Оформление окна

- `WindowStyle="None"` + `WindowChrome`. **`AllowsTransparency="True"` не используется** — он отключает аппаратное ускорение и ломает Mica и скругления.
- Фон Mica и скругление углов 12 px — через `DwmSetWindowAttribute` (`DWMWA_SYSTEMBACKDROP_TYPE`, `DWMWA_WINDOW_CORNER_PREFERENCE`).
- `PerMonitorV2` в `app.manifest`.
- `Topmost = true`.

## 7. Модель ввода

### Поле заголовка

- Однострочное. Многострочности нет.
- Одновременно **создаёт и фильтрует**: по мере ввода список фильтруется подстрокой по заголовкам, совпадения подсвечиваются. Заметки в поиске не участвуют. Сравнение регистронезависимое (`OrdinalIgnoreCase`).
- Фильтр идёт **только по активным задачам**. Выполненные и удалённые в него не попадают: набранный заголовок уже выполненной задачи даёт пустой список и подсказку «Enter — создать». Дубль в этой ситуации создаётся сознательно.
- Пустое поле — полный список.
- Совпадений нет — пустой список и подсказка «Enter — создать».
- **`Enter` создаёт задачу всегда**, даже при точном совпадении с существующей. Поле очищается, список возвращается к полному.
- **Черновик сохраняется:** несохранённый текст поля восстанавливается при следующем открытии окна. Вместе с ним восстанавливается и фильтр — окно открывается в отфильтрованном виде. Правилу из раздела 10 это не противоречит: текст виден в поле ввода, значит состояние списка объяснено.
- Предел длины заголовка — 500 символов. При наборе с клавиатуры ввод обрезается. При **вставке** текста длиннее 500 символов первые 500 идут в заголовок, остаток — в поле заметки, которое при этом раскрывается; фокус остаётся в заголовке.

### Поле заметки

- Раскрывается по `Tab` из заголовка, фокус переходит туда. При **пустом заголовке `Tab` не делает ничего** (без сообщений об ошибке).
- Многострочное. `Tab` внутри уводит фокус дальше, табуляцию не вставляет. `Shift+Tab` — обратно в заголовок.
- `Esc` возвращает фокус в заголовок, но **поле остаётся раскрытым, пока в нём есть текст**. Сворачивается только пустое. Скрытого состояния «невидимая заметка у создаваемой задачи» быть не должно.
- Фильтрация списка во время написания заметки **продолжает работать** в том состоянии, в каком была.

### Правило Enter (сквозное для приложения)

> **`Ctrl+Enter` создаёт задачу откуда угодно. `Enter` зависит от поля: в однострочном заголовке — создаёт, в многострочной заметке — переносит строку.**

| Где | `Enter` | `Ctrl+Enter` |
|---|---|---|
| Заголовок | создать, окно остаётся открытым | создать и закрыть окно |
| Заметка | новая строка | создать |

## 8. Карточка задачи

**Двухъярусная, ~64 px.** Второй ярус содержит только иконки.

```
┌────────────────────────────────────────┐
│▌ ☐ Заголовок задачи, до N строк    (!) │  ярус 1
│    (💬)                          (🗑)  │  ярус 2
└────────────────────────────────────────┘
 ▲ полоска важности 3 px
```

| Элемент | Позиция | Поведение |
|---|---|---|
| Чекбокс выполнения | ярус 1, слева от заголовка | **виден всегда и всегда полной яркости** — правило прозрачности 40/70/100% на него не распространяется. Клик отмечает задачу выполненной, повторный клик по отмеченной возвращает её в активные |
| Заголовок | ярус 1, после чекбокса | лимит строк настраиваемый, по умолчанию 2, диапазон 1–4; дальше многоточие + полный текст в подсказке при наведении |
| Восклицательный знак (важность) | ярус 1, справа | тусклый, пока карточка не активна |
| Облачко заметки | ярус 2, слева | **видно всегда**: активный цвет — заметка есть, тусклое — нет |
| Удалить | ярус 2, справа | тусклое; при наведении на саму иконку — красная |
| Полоска важности | левый край, 3 px | акцентный цвет, видна постоянно у важных задач |

Отдельной иконки «Готово» во втором ярусе нет: выполнение — это чекбокс. Он поставлен слева от начала заголовка потому, что это главный смысловой элемент списка задач, и он не должен быть приглушён до наведения.

### Прозрачность иконок

| Состояние | Непрозрачность |
|---|---|
| Карточка не активна | 40% |
| Наведение/выделение карточки | 70% |
| Наведение на саму иконку | 100% |

- «Активна» = наведён курсор **или** карточка выделена стрелками.
- **Место под иконки резервируется всегда.** Иконки меняют только прозрачность — текст и границы карточки не должны прыгать при наведении.
- Порог читаемости: ниже ~35% непрозрачности на Mica-фоне иконка перестаёт читаться как элемент. 40% — нижняя граница.

### Клик по облачку

- Заметка есть — карточка разворачивается, показывается текст.
- Заметки нет — открывается пустое поле для её добавления.
- Состояние «развёрнуто» **запоминается между открытиями окна** (поле `is_expanded` в БД).

## 9. Список

### Порядок

- Новые задачи добавляются **в начало списка** — визуально это сторона, где стоит поле ввода (раздел 5). Кратковременная подсветка новой строки акцентным цветом ~400 мс как подтверждение создания.
- **Важность не влияет на порядок** — только подсветка. Приоритет выражается положением в списке.
- Порядок ручной: drag&drop и `Alt+↑↓`.
- Технически — `sort_order REAL`: вставка между соседями считается как `(a+b)/2`, перенумерация всего списка в обычной работе не нужна.
- **Но потолок у этого есть.** Шаг между соседними задачами при создании списка — `1000.0`. Если при вставке разрыв между соседями меньше `1e-6`, точность `double` исчерпана: порядок начнёт молча ломаться (`a == b`). В этом случае список перенумеровывается заново с шагом `1000.0`, и только после этого делается вставка. Проверка разрыва обязательна на каждой вставке — иначе примерно после 50 перетаскиваний в одно и то же место порядок поедет без единой ошибки в логе.

### Drag&drop

- Работает только при **пустом поле ввода**. При активном фильтре перетаскивание заблокировано: курсор не меняется на «захват», карточки не поднимаются. Иначе позиция вставки неоднозначна из-за скрытых фильтром задач.
- По той же причине при активном фильтре **не работает и `Alt+↑↓`**: соседи по списку скрыты, и перестановка выглядела бы как «ничего не произошло» или как прыжок через невидимые задачи.
- Перетаскивание **в блок «Выполнено сегодня» и обратно запрещено**. Выполнение и возврат — только чекбоксом, `Space` или `Ctrl+Z`.
- Анимация в v1 базовая.

### Выполнение

Выполнение отмечается **чекбоксом** в карточке (раздел 8) или клавишей `Space` на выделенной строке.

1. Чекбокс проставляется, карточка получает зачёркивание и приглушение, остаётся на месте ~1.5 с.
2. Уезжает в блок **«Выполнено сегодня · N»** в конце основного списка. Блок по умолчанию свёрнут, разворачивается кликом по строке.
3. Внутри блока — такие же карточки, но с проставленным чекбоксом. Сортировка по времени выполнения, свежие сверху.
4. Возврат — снятие чекбокса мышью, `Space` на строке в развёрнутом блоке или `Ctrl+Z`. Задача встаёт **на прежнее место** (`sort_order` не менялся).
5. Блок сбрасывается по локальной полуночи. Проверка при каждом показе окна — на случай, если приложение работало всю ночь.
6. **Выполненные задачи из БД не удаляются** — нужны для будущей статистики. Но экрана истории в v1 нет: после полуночи вчерашние выполненные исчезают из интерфейса совсем и до v3 их не увидеть. Это сознательно.

### Удаление

- Мягкое: проставляется `deleted_at`. Из списка и из статистики исключается немедленно.
- Откатить удаление можно только через `Ctrl+Z` или тост «Отменить», то есть в пределах текущего запуска: стек отмены живёт в памяти (раздел 11), корзины в v1 нет.
- Физическая очистка — в **той же полуночной проверке**, что и сброс блока «Выполнено сегодня»: всё, где `deleted_at` старше суток, удаляется из БД. Привязывать очистку к старту приложения нельзя — оно резидентное, старты редкие, и мусор копился бы неделями.

### Пустое состояние

Тусклый плейсхолдер с текстом, что задач нет.

## 10. Клавиатурная карта

### Поле заголовка

| Клавиши | Действие |
|---|---|
| `Enter` | создать задачу, поле очищается, окно остаётся открытым |
| `Ctrl+Enter` | создать и закрыть окно |
| `Tab` | раскрыть поле заметки (только если заголовок не пуст) |
| `↓` / `Ctrl+J` | перейти в список |
| `Esc` | скрыть окно, черновик сохранить |
| `F1` | шпаргалка по горячим клавишам |

Шпаргалка висит на `F1`, а не на `?` в пустом поле: иначе заголовок задачи невозможно начать со знака вопроса — первый символ съедала бы справка.

### Поле заметки

| Клавиши | Действие |
|---|---|
| `Enter` | новая строка |
| `Ctrl+Enter` | создать задачу |
| `Shift+Tab` | вернуться в заголовок |
| `Esc` | вернуться в заголовок, непустое поле остаётся раскрытым |

### Список

| Клавиши | Действие |
|---|---|
| `↓` / `Ctrl+J`, `↑` / `Ctrl+K` | навигация |
| `Space` | выполнить / вернуть из выполненных |
| `Enter` | правка заголовка на месте |
| `Tab` из правки | открыть заметку этой задачи |
| `Delete` | удалить |
| `→` | развернуть заметку |
| `←` | свернуть заметку |
| `Alt+↑` / `Alt+↓` | переставить задачу |
| `!` или `Ctrl+I` | переключить важность |
| `Esc` | вернуться в поле ввода (окно не закрывается) |
| `Esc` повторно | скрыть окно |
| `↑` с первой строки | вернуться в поле ввода |

### Правка на месте

- Заголовок: `Enter` — сохранить, `Esc` — **откатить изменение**.
- Заметка (открытая по `Tab` из правки): `Enter` переносит строку, поэтому сохранение — по уходу фокуса и по `Esc`. **`Esc` откатывает только заголовок; текст заметки сохраняется.** Так сделано потому, что заметку пишут длинно и потерять её по случайному `Esc` дороже, чем потерять правку в одну строку.

### Мышь

| Действие | Результат |
|---|---|
| Одиночный клик по карточке | выделить (то же выделение, что стрелками) |
| Двойной клик по заголовку | правка заголовка на месте |
| Клик по чекбоксу | выполнить / вернуть из выполненных |
| Клик по облачку | развернуть заметку, а если её нет — открыть пустое поле |
| Клик по мусорке | удалить |
| Клик мимо окна | ничего, окно не прячется |

### Глобально

| Клавиши | Действие |
|---|---|
| `Ctrl+Z` | отменить |
| `Ctrl+Shift+Z` | повторить |
| `F1` | шпаргалка по горячим клавишам |

`Ctrl+Z` **всегда** уходит в стек отмены операций, в том числе когда каретка стоит в поле ввода. У обоих текстовых полей встроенная отмена отключается (`IsUndoEnabled = false`) — иначе одна и та же комбинация в одном месте отменяла бы набор текста, а в другом удаление задачи.

**Важно:** пока каретка в поле ввода, `Space` печатает пробел. Фокус должен физически уходить в список по `↓`, и выделение в списке визуально отличается от простого наведения мыши.

### После создания задачи

Поле ввода очищается, список возвращается к полному состоянию — чтобы не остаться в непонятном отфильтрованном виде и не решить, что задачи пропали.

**Только после создания.** Операции над задачами в списке — выполнение, важность, удаление, перестановка, правка — черновик в поле ввода **не трогают**: иначе `↓` + `Delete` стирал бы уже набранный текст следующей задачи.

## 11. Отмена действий

- Стек на 20 операций, **только в памяти**, между запусками не сохраняется.
- Каждая операция хранит обратное действие: создание → удаление, выполнение → снятие, удаление → восстановление, правка → прежний текст, важность → прежнее значение, перестановка → прежний `sort_order`.
- Уведомление — **внутренний тост снизу окна** («Задача удалена · Отменить»), не системное. Системное вы не увидите: окно и так поверх всех.

## 12. Данные

### Расположение

`%APPDATA%\QuickJot\tasks.db` — SQLite в режиме WAL, запись синхронная на каждое действие. При старте копия БД кладётся в `backups\`, хранятся последние 5.

### Схема

```sql
CREATE TABLE tasks (
  id           TEXT PRIMARY KEY,   -- GUID, не автоинкремент
  title        TEXT NOT NULL,
  notes        TEXT,
  is_flagged   INTEGER NOT NULL DEFAULT 0,
  is_expanded  INTEGER NOT NULL DEFAULT 0,
  sort_order   REAL NOT NULL,
  completed_at TEXT,               -- NULL = активна
  deleted_at   TEXT,               -- мягкое удаление
  created_at   TEXT NOT NULL,
  updated_at   TEXT NOT NULL
);

CREATE INDEX idx_tasks_active ON tasks(deleted_at, completed_at, sort_order);

CREATE TABLE settings (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL
);
```

- Все временные метки — **UTC в ISO-8601**.
- `id` — GUID, чтобы позже безболезненно прикрутить синхронизацию.
- `sort_order` типа `REAL` — см. раздел 9.
- Колонки `due_at`, `remind_at`, `project_id` сознательно **не добавлены**: `ALTER TABLE ADD COLUMN` в SQLite дёшев. А `id`, `sort_order` и мягкое удаление менять потом дорого, поэтому они сразу правильные.
- Черновик поля ввода, размеры окна, угол привязки — в таблице `settings`.

## 16. Технические грабли (WPF / Win32)

1. **Фокус в поле ввода.** `SetForegroundWindow` из фонового процесса Windows блокирует: окно покажется, но каретка в поле не встанет — а это вся суть приложения. Рабочий приём: перед показом сохранить `GetForegroundWindow()`, затем `AttachThreadInput` к потоку этого окна на время активации → `Show()` → `Activate()` → `Focus()` на TextBox → отсоединиться.
2. **Возврат фокуса.** При скрытии окна фокус возвращается сохранённому HWND — иначе человек вырывается из контекста, в котором работал.
3. **Прогрев окна** на старте (см. раздел 3).
4. **Хоткей — на message-only окне**, не на главном.
5. **`AllowsTransparency` не использовать.**
6. **Мультимонитор и per-monitor DPI** — `PerMonitorV2` в манифесте, позиционирование по `MonitorFromPoint` + `WorkArea`. Классический источник багов при связке «ноутбук + внешний монитор» с разным масштабом.
